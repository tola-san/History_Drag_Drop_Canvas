# History Drag & Drop Canvas

A Next.js App Router starter with TypeScript, Tailwind CSS, shadcn/ui, Lucide, React Hook Form, and Zod. Source lives in src/ and imports use @/*.

## Run the existing project

Requires Node.js 22.18+ (Node.js 24 recommended) and npm.

```powershell
cd D:\java-SpringBoot-learning\auth-basic
npm install
Copy-Item .env.local.example .env.local
npm run dev
```

Open http://localhost:3000/login or http://localhost:3000/register. For the included Java backend, keep NEXT_PUBLIC_API_URL as your frontend origin and set SPRING_BOOT_API_URL to your Java origin. See the final section for the default proxy setup. Restart development after changing it. Production public environment values are embedded at build time: set the URL before npm run build.

## Reproduce the initial setup

Run these from the parent directory only when creating a new project:

```powershell
npx create-next-app@latest auth-basic --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --yes --disable-git
cd auth-basic
npm install react-hook-form @hookform/resolvers zod lucide-react
npx shadcn@latest init --defaults --yes
npx shadcn@latest add button input label checkbox --yes
```

All required shadcn components are included; you do not need to run the CLI again for an existing checkout. components.json records the style, aliases, and Lucide icon library. Components are owned source code you can edit.

## How the forms work

1. Pages render the shared AuthShell and reusable LoginForm or RegisterForm.
2. React Hook Form manages values; the Zod resolver validates on submit and focuses the first invalid input.
3. Each valid submission fetches a fresh session-bound CSRF token, then sends JSON with credentials: "include".
4. A successful HTTP response from the real API is required for success feedback. Passwords and session identifiers are never persisted in browser storage.
5. Login stays on the page after success because no protected application destination was requested. Add your application redirect only after the backend confirms authentication.

Passwords require 12–128 characters for registration. Login does not impose new-account password rules on existing users. Strength is a simple educational estimate, not an entropy calculation. Backend validation remains authoritative. Registration sends termsAccepted but omits confirmPassword.

## Spring Boot API contract

The Java backend is a separate application; this project does not implement a database or authenticate users by itself.

| Method | Path               | Request / response                                                                                                                                                            |
| ------ | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | /api/auth/csrf     | 200 JSON: {"token":"session-bound-token","headerName":"X-CSRF-TOKEN"}. Materialize Spring's CsrfToken before returning; use Cache-Control: no-store.                          |
| POST   | /api/auth/login    | JSON: {"email":"you@example.com","password":"...","rememberMe":false}. Return 200 or 204 only after authentication and SecurityContext persistence. Set the session cookie.   |
| POST   | /api/auth/register | JSON: {"email":"you@example.com","password":"...","termsAccepted":true}. Return 201/202/204 according to your account verification flow. Do not assume registration signs in. |

Return JSON or an empty successful body, not a redirect to a login page. The client rejects redirects. Use 401 for invalid credentials, 403 for invalid CSRF/denied access, and 429 for throttling. Other failures intentionally show a generic error without reflecting backend stack traces or user details.

Spring configuration responsibilities:

- Keep CSRF enabled on login and registration as well as other unsafe requests. Expose the token endpoint anonymously and return the token value Spring expects for your configured request handler. A controller can return CsrfToken.getToken() and getHeaderName() from the injected token. GET /csrf must materialize the token.
- Permit anonymous access to these authentication endpoints without bypassing CSRF checks. Use a JSON authentication controller/filter; default Spring formLogin expects form-encoded parameters and is not compatible with this contract.
- Authenticate through AuthenticationManager, apply the configured session authentication strategy (including session fixation protection), and explicitly save the authenticated SecurityContext through the configured SecurityContextRepository before returning success. Do not merely check a password and return 200.
- CORS must allow the exact frontend origin, allow credentials, permit GET/POST/OPTIONS and Content-Type plus the configured CSRF header. Never combine credentials with an origin wildcard. Process CORS preflight before Spring Security.
- Rotate session identifiers at authentication; clear/rotate CSRF state as appropriate. This client fetches a new token for every submission.
- Use an HttpOnly, Secure session cookie in production. For cross-site frontend/API origins use SameSite=None; Secure (HTTPS required). For same-site deployments, prefer SameSite=Lax where appropriate. JavaScript cannot set these server cookie attributes.
- Cross-site cookies can still be blocked by browser privacy settings. Prefer HTTPS custom subdomains sharing a registrable domain (for example app.example.com and api.example.com), or a deliberate same-origin reverse proxy. An unrelated frontend domain and onrender.com are cross-site.
- rememberMe is a backend session-duration request; the frontend cannot extend the session. Implement an explicit server policy with suitable cookie lifetime, server expiry, rotation and revocation. Do not issue a persistent session merely because the browser asks.
- Validate all fields again, enforce terms acceptance and the same password length policy, hash passwords with an appropriate password encoder, normalize emails consistently, and enforce uniqueness in PostgreSQL. Throttle authentication and recovery endpoints. Never log passwords or request bodies containing credentials.
- Before adding protected UI, implement an authenticated current-user endpoint and authorization checks on every backend resource. Hiding a frontend page is not authorization.

## Render and PostgreSQL

Deploy Spring Boot as a Render web service and PostgreSQL as a managed database. Configure the database connection on the backend only (for example SPRING_DATASOURCE_URL, SPRING_DATASOURCE_USERNAME, SPRING_DATASOURCE_PASSWORD); convert Render connection information into the JDBC format expected by your driver. Keep credentials in Render's environment settings. Use migrations rather than automatic production schema creation.

Configure HTTPS/proxy handling and the backend cookie/CORS settings above. For proxy mode, set NEXT_PUBLIC_API_URL to the HTTPS frontend origin and SPRING_BOOT_API_URL to the HTTPS backend origin before building. No database secrets belong in NEXT_PUBLIC_* variables.

## Before real-user launch

Replace /terms and /privacy with your actual policies. /forgot-password currently explains that recovery is unavailable; it does not pretend to send an email. Add a real backend recovery flow before offering self-service reset. Confirm the backend contract, cookies, CSRF rotation, remember-me expiry, and access control in the deployed browser environment.

## Connect the included Java backend

The default configuration uses NEXT_PUBLIC_API_URL=http://localhost:3000 and SPRING_BOOT_API_URL=http://localhost:8080. Next.js maps browser /api/auth/* requests to Java /auth/* routes. Cookies stay on the frontend origin and CSRF remains enabled. This default proxy setup supersedes the direct API setup instructions above.

Start auth-service separately following its README. Its existing Compose configuration reads its own .env:

```powershell
cd ..\auth-service
docker compose up --build -d
```

For production proxy mode, set NEXT_PUBLIC_API_URL to the HTTPS frontend origin and SPRING_BOOT_API_URL to the HTTPS Render API origin before building. This requires a Next.js server deployment. Use host-only session cookies without a backend-specific Domain attribute. No database secrets belong in Next.js.

For direct API mode instead, remove SPRING_BOOT_API_URL and set NEXT_PUBLIC_API_URL to a backend exposing /api/auth/* with credentialed CORS.

If Java is offline, authentication correctly fails. The included learning backend does not yet implement terms acceptance or remember-me duration and has a narrower BCrypt password limit. Align those backend policies before production.

## Onboarding and production API

The protected /onboarding route now provides the four setup steps, React Flow canvas, animated folders and temporary photo previews. Login verifies the real session and redirects to onboarding. See [ONBOARDING_API.md](ONBOARDING_API.md) for persistence endpoints still needed in Java.

The configured upstream is https://java-spring-security-auth.onrender.com. Keep NEXT_PUBLIC_API_URL as the frontend origin and SPRING_BOOT_API_URL as the Render origin. The variable name must be spelled SPRING_BOOT_API_URL.
